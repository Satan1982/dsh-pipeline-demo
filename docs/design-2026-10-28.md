# 自动化 AI 编程：架构设计（2026-10-28）

> 一句话：把「人写工单 → agent 干活 → 门禁判绿 → 评审挑刺 → 出 PR」做成可无人值守的流水线。
> **自动到 PR 为止**；合并要 `merge:auto`，发版永远人工。

这份文档讲「为什么这么设计」，[`manual.md`](manual.md) 讲「怎么用」。

---

## 1. 边界：自动到哪里，哪里必须是人

先划边界，否则「全自动」会变成一个吞钱的坑。

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 提需求、写验收命令 | **人** | 验收标准是这件事的唯一定义。让 agent 自己定义「做完了」= 自己批自己的作业 |
| 拆任务、排依赖 | 人写规格，`ci/plan.mjs` 建单 | 拆解是设计决策；机械化建单只是省手工 |
| 改代码、跑自测 | agent（headless） | 这是真自动的部分 |
| 判绿 | **调度器自己跑** `scripts/verify.sh` | 不信 agent 的自述：它说跑过了不算，同一个 worktree 里再跑一遍 |
| 挑刺 | 机械评审 + 两个不同家族模型并行的语义评审团 | 单模型自评不可靠；换家族才有交叉视角 |
| 合并 | 默认**停手等人**；工单带 `merge:auto` 才自动 squash | 合并是不可回补动作，默认不放手 |
| 发版 / tag / 改门禁 | **人**（改门禁还要 `DSH_ALLOW_GATE=1` + `allow:gate` 标签） | 门禁是裁判，不能被选手改 |

一句话：**机器负责「做」和「验」，人负责「定义验收」和「放行不可回补的动作」。**

## 2. 分层

```
┌─────────────────────────────────────────────────────────────────┐
│ 触发层  登录自启(HKCU Run) / 计划任务每 5 分钟 --once / 手工 --ensure │
├─────────────────────────────────────────────────────────────────┤
│ 调度层  ci/dispatch.mjs：单实例锁 → 轮询 → 领取 → 并发池 → 收口      │
├─────────────────────────────────────────────────────────────────┤
│ 执行层  ci/headless-task.sh：PATH / 模型路由 / 权限档 → DSH headless │
│         隔离工作区：<盘>/.worktrees/issue-N（core.hooksPath=.githooks）│
├─────────────────────────────────────────────────────────────────┤
│ 门禁层  scripts/verify.sh：lint → test → 测试数基线 → 断言指纹 → build → pack │
│         + 提需求人写的「验收命令」（agent 改不动）                    │
├─────────────────────────────────────────────────────────────────┤
│ 审查层  ci/review.mjs（机械）+ ci/semantic-review.mjs（语义评审团）    │
│         ci/verdict.mjs（VERDICT: PASS/FAIL 裁决）                    │
├─────────────────────────────────────────────────────────────────┤
│ 记忆层  docs/failures.jsonl（失败指纹，重试前回灌）→ ci/distill-failures.mjs → Hindsight │
├─────────────────────────────────────────────────────────────────┤
│ 成本层  ci/prices.mjs（元/百万 token）、usage.jsonl、单任务/单日闸门    │
│ 恢复层  ci/pool-block.mjs（判据）+ ci/blocked-recovery.mjs（自动重投） │
└─────────────────────────────────────────────────────────────────┘
```

数据流（一轮）：

```
issue(agent:ready)
  → 打 agent:working，建 worktree，写 .dsh/PLAN.md
  → headless agent 干活（第 1 次弱模型，第 2 次起升 strong）
  → 自己跑门禁 → 红了就带失败指纹重试（最多 3 次）
  → 提需求人的验收命令 → exit 0 才继续
  → 机械评审 → 语义评审团（免费档 → 付费档升级）
  → 推 agent/issue-N 分支，开 PR
  → checkAgentPRs：冲突就 rebase、CI 红就取日志回灌修
  → CI 绿：有 merge:auto 自动 squash 合并关单，否则停在 PR 等人
```

## 3. 八条关键机制

### 3.1 一单一隔离 worktree
每个工单一个 `git worktree`，`core.hooksPath` 指向 `.githooks`，`.dsh/` 进 `info/exclude`（PR 里看不见）。
**为什么**：并行跑两个 agent 时，绝不能有两个进程改同一份工作树；隔离也让「删掉重来」变成一条 `git worktree remove`。

### 3.2 PLAN.md 是唯一验收清单
调度器按 issue 生成 `.dsh/PLAN.md`（目标 / 验收标准 / **验收命令** / 约束 / 红线），agent 和两层评审都读它。
验收命令是**提需求的人写的**、agent 改不动，调度器自己在 agent 的产物上跑一遍。
**为什么**：agent 最擅长的作弊方式是「写一个断言自己结论的测试」。外部验收命令把这条堵死。

### 3.3 门禁不信自述，只认退出码
`scripts/verify.sh` 六步：lint（含 `check-imports` 抓漏 import）→ 单测 → **测试数基线**（降了就红）→ **断言内容指纹**（改断言、删断言、加断言未 bless 都红）→ build → pack。
**为什么**：删掉失败的测试、把 `2` 改成 `2.0` 来凑绿，是 AI 编程最典型的退化路径。指纹让「偷偷削弱测试」变成提交时就失败的事。

### 3.4 两层评审：形状 + 意图
- 机械评审（`review.mjs`）：只看 diff 形状——调试残留、删测试、基线不同步、动门禁、没改任何文件。
- 语义评审团（`semantic-review.mjs`）：两个**不同家族**的模型并行判「是否真的满足验收」，任一 block 即 block；免费档判不出结论就升级到付费面板。
**为什么**：同家族模型互相认同；机械规则抓不住「代码能跑但没做要求的事」。

### 3.5 失败记忆
每次失败归一成指纹写 `docs/failures.jsonl`（上限 500 行），下次重试前把「同类失败上次怎么修的」回灌给 agent；每天蒸馏进 Hindsight `pipeline::failures` 跨机共享。
**为什么**：没有记忆的 agent 会在同一个坑里摔三次，每次都花钱。

### 3.6 成本与模型：免费优先，花钱要人点头
三档：免费池（¥0）→ `model:strong` → `model:paid`（`deepseek-flash`）。
`usage.jsonl` 按官方价折算人民币；单任务超 `DSH_TASK_MAX_CNY`（0.5 元）告警并暂停本批，单日超 `DSH_DAY_MAX_CNY`（5 元）当天不再领取。
**关键决策**：免费池不可用（额度耗尽 / 连续 2 次 0 token）**不自动切付费**，而是挂起（`agent:blocked`）。
理由见 §5.1。

### 3.7 并发、锁、挂起与自动恢复
- **锁**：`LOG_DIR/dispatch.lock` 用 `writeFileSync(..., {flag:'wx'})` 原子创建；持有者心跳刷 `at`；超过 `超时 + 10 分钟` 判定陈旧；两个实例同时判陈旧时回头复核 `ownsLock()`，输者让位；`release()` 只删自己那份。
- **并存是常态**：计划任务每 5 分钟 `--once` 敲门，与手动 `--ensure` 拉起的常驻会撞。日志里出现「接管陈旧锁 / 锁已被接管，常驻进程退出」属**正常**，不是故障。
- **挂起与恢复（2026-10-28 新增）**：池子不可用 → 挂起 + 本地记 `blocked-state.json` → 按 5/10/20/40/60 分钟退避探活（判据：至少一个 `ok` 模型，`stale` 不算）→ 恢复则自动摘 `agent:blocked`、打 `agent:ready` 重跑 → 同一单最多自动重投 3 次 → 用完打 `agent:blocked:manual` 停下等人。

### 3.8 标签自动补齐（2026-10-28 新增）
调度器拿锁后、轮询前跑一次 `ensureLabels()`（清单在 `ci/labels.mjs`，14 条）：列出现有标签 → 缺的用 `POST /repos/:o/:r/labels` 建上 → 日志 `[labels] 补齐 N 个缺失标签：…`。读不到/建不了只记一行、不阻塞任务；`--dry-run` 只打印不发请求；`dep-on:<任务号>` 不纳入（名字随任务号变）。
**为什么**：GitHub 打一个不存在的标签是**静默丢弃**的——不报错、issue 上也不多东西。2026-10-28 实测：`agent:blocked:manual` 当时没建，自动恢复的「交给人」分支打完等于没打，人从标签上看不出要接手；`model:free` 也一直缺，意味着这条人工开关此前是假的。标签是人与调度器之间唯一的状态接口，它的静默失败等于状态丢失。

## 4. 状态机（标签）

```
              ┌──────────── 人写工单（模板自动打 agent:ready）
              ▼
        ┌──────────┐  领取   ┌───────────┐  通过  ┌───────────┐
        │agent:ready│───────▶│agent:working│──────▶│ agent:done │
        └──────────┘        └─────┬─────┘        └───────────┘
              ▲                   │ 失败 3 次 / 池不可用
              │                   ▼
              │            ┌──────────────┐
              │  池恢复    │ agent:blocked │──重投 3 次用完──▶ agent:blocked:manual（停）
              └────────────┴──────────────┘
                              │ 重试耗尽且非环境问题
                              ▼
                        agent:failed（人改完去掉标签重新打 ready）
```

修饰标签：`model:strong` / `model:paid`（提档）、`merge:auto`（自动合并）、`dep-on:Tn`（依赖）、`allow:gate`（允许改门禁）、`readonly:ok`（只读调查单）、`acceptance:optional`（免验收命令）、`verdict:strict`（缺 VERDICT 即失败）。

## 5. 决策记录（为什么这样，而不是那样）

### 5.1 免费池不可用 → 挂起，不自动切付费
额度耗尽、余额不足是**环境状态**，不是「这单写错了」。环境坏了还继续跑，等于用付费的钱去跑一个本来免费的任务，而且人不知道。
要做的是：挂起 + 说清三条恢复路径（等 / 等池好手动重投 / 打 `model:paid` 授权花钱）。
要恢复旧的自动切付费：`DSH_FREE_POOL_BLOCK=0`（会花钱，慎重）。

### 5.2 判据与动作分离
`pool-block.mjs`、`blocked-recovery.mjs` 都是**纯函数 + 单测**，网络与 GitHub 动作留在 `dispatch.mjs`。
**为什么**：判定逻辑（退避、重投上限、什么时候算「恢复」）是最容易写出边界 bug 的地方，必须能在毫秒内被单测覆盖；网络动作不可回补，要单独审。

### 5.3 挂起之后要能自己好起来，但重投必须有上限
只挂起不恢复，无人值守时单子会永远躺着；只恢复不设上限，池子抖一下就是「重投 → 立刻挂 → 再重投」的无限循环。
所以：退避探活 + 最多 3 次 + 计数跨次继承（`blockTask` 重新挂起时继承 `requeues`）。

### 5.4 「恢复了」宁可判严
`stale` 不算恢复（要重试/换档），只认 `ok`。
**为什么**：误判一次就是白跑一个任务（真金白银 + 一次失败指纹污染）；多等一轮只花几分钟。

### 5.5 默认停在 PR，不默认合并
CI 绿 + 评审过只代表「机械上没错」，不代表「这是我要的」。所以 `merge:auto` 是**人主动打的标签**，不是默认。

### 5.6 两实例并存靠锁让位，不靠「只许一个」
计划任务与常驻天生会撞。与其禁止并存，不如让撞到的那一个让位并留日志——崩溃、重启、手工介入都变成非事件。

### 5.7 陈旧锁按模式判，不按统一超时（2026-10-28）
一把锁判陈旧原来只有一套口径（`DSH_TASK_TIMEOUT_MS + 10min`，默认 40 分钟）。但两种进程的「心跳形状」完全不同：
常驻每 60 秒刷一次，停 3 分钟就是卡死；`--once` 领到单后要在 worktree 里干到超时，这期间**心跳是停的**，
用 3 分钟口径会把正常干活的判死，两个进程抢同一棵工作树。
所以锁里写 `mode`，`serve` 用 3 分钟（`DSH_LOCK_BEAT_STALE_MS`），`once` 沿用 40 分钟；老锁没有 `mode` 时按 `once`（宁可多等，不误杀）。
判据抽成 `ci/lock-policy.mjs` 纯函数，边界条件由单测守。

### 5.8 提交只收「有意的改动」，不 `git add -A`（2026-10-28）
`git add -A` 会把任何自动生成的产物卷进下一次提交：实测成本报表每天自动写 `docs/cost-report.md`，
于是任何一次不相关的提交都带着几十行报表噪声。改两处：报表输出移到 `.logs/`（不入库），
`ci/land.sh` 默认 `git add -u`（只收已跟踪文件的改动），未跟踪的新文件要 `DSH_LAND_ALL=1` 才收。

## 6. 扩展点

| 想加什么 | 动哪里 | 注意 |
|---|---|---|
| 新的机械规则 | `ci/review.mjs` 的检查表 | 会改变已有 PR 的判定，先在 `docs/failures.jsonl` 里找反例 |
| 新的门禁步骤 | `scripts/verify.sh` | 需要 `DSH_ALLOW_GATE=1` + 工单 `allow:gate`；基线要 `--bless` |
| 换模型档位 | `headless-model*.yml` / `model-policy.mjs` | 免费池选型走 `fm.py pick`，不要硬编码模型名 |
| 同账号多库 | `repos.json`（未实现） | 每库要独立 worktree / 锁 / 日志，否则并发会串 |
| 新的一类恢复动作 | `ci/*.mjs` 纯函数 + `dispatch.mjs` 网络动作 | 先写单测，再接网络 |

## 7. 红线

- 不许删/改已有测试与断言来凑绿；基线必须同 PR `bash scripts/verify.sh --bless`。
- 不许改 `.github/workflows/`、`scripts/verify.sh`、`scripts/assert-guard.mjs`、`ci/*`（需要时 `allow:gate`）。
- 不许留调试占位符 / 断点 / 只跑单个用例的标记。
- 不许加依赖；一 PR 一个垂直切片。
- 发版、tag、`git push --force`、改已推送历史：永远人工。

以上前四条由 `.githooks/pre-commit`（`ci/precommit.mjs`）在提交时强制，`--no-verify` 才能绕过——绕过等于告诉别人「这次不用看门」。
