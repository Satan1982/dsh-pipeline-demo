## 1 问题

语义评审判的是「diff 是否满足验收标准」，判不了可数事实：删几条断言再把基线同步改小、
新增一堆没人用的符号、验收日志末尾是 FAIL 但退出码 0——这些都能过语义评审。

## 3 判定口径

### 判据 1：断言增删 ↔ 基线（硬）

- 断言计数与 `scripts/verify.sh:104` 完全同口径：`grep -o 'assert.' src/*.test.js ci/*.test.mjs` 的出现次数；
- 期望 head.asserts = base.asserts + diff 新增断言出现数 - diff 删除断言出现数；不等 → fail，并指出 `scripts/test-baseline.txt:1`；
- head.tests < base.tests → fail（测试数不许下降）。

### 判据 2：新增导出符号的测试引用（warn）

- `findNewExports` 只看新增行里的 `export function/class/const`；
- 在所有 `*.test.js` / `*.test.mjs` 里按标识符边界计引用，0 引用 → warn（可能由 CLI/外部调用，故不硬拦）。

### 判据 3：证据一致性（硬）

- 声明 PASS 但实际 exit≠0 → fail（伪绿）；
- 声明 PASS 但输出末尾 `VERDICT:` 不是 PASS → fail；
- exit=0 但输出末尾 `VERDICT: FAIL` → fail（结论与退出码矛盾）。
