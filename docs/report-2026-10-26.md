## 四、这套东西现在能做什么、不能做什么

能：写 Issue（四段：目标 / 验收标准 / 验收命令 / 约束）→ 打 `agent:ready` → 无人干预跑到 PR；
CI 红了自动回灌日志修复（同 PR 最多 3 次）；分支冲突自动 rebase（基线类自动重算、源码类交 agent）；
测试/断言基线被删或被改写会红；语义评审拦「像那么回事但没满足验收」；打了 `merge:auto` 就一路合到关闭。

不能（明确标注，不假装）：

1. 不打 `merge:auto` 就不会自动合并——这是刻意的，产品调研里没有一家把合并交给 agent。
2. 29B 模型解多文件源码冲突不可靠（实测一次 41s 成功、一次 522s 失败），失败即转人工。
3. 失败记忆只落在 `docs/failures.jsonl`，还没有回流到 Hindsight 知识页（同一坑换台机器仍要重踩）。
4. 语义评审模型偶尔超时（Qwen3.5-122B，超时 240s），超时按「跳过」处理但会留一行告警。
5. tag 与 GitHub Release 仍是人工（`bash /d/code/.secrets/gh-push.sh vX.Y.Z`）。
