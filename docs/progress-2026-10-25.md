## 三、夜间顺带修掉的三个真故障

1. **两个调度器并发**：计划任务每 5 分钟一轮，手动 `--once` 撞上去，两个进程抢同一 worktree
   和分支，互相 `worktree remove --force`，外部表现是「agent 未产生任何改动」这种假故障。
   → `.logs/dispatch.lock` 单实例锁（`flag:'wx'` 建文件 + pid 存活探测 + 超时接管）。
   实测：d1 正常跑，d2 打「已有调度器在跑（pid=…）本次直接退出」；结束锁自动释放。
   计划任务 17:30:56 与 17:40:56 两轮都是在锁上被挡住的，没有互相破坏。
2. **`BUNDLE_DIR` 拼错**：`node/bin/node.exe` 只上溯两级落到 `dependencies/node`，
   `PNPM_CLI` 指向不存在的文件，门禁打包步骤必挂——issue #27 第 1 次「agent 说 verify OK、
   调度器自己跑却红」就是这个。→ 上溯三级；`verify.sh` 遇到不存在的 `PNPM_CLI` 直接报路径。
3. **29B 模型撞 TPM 限流**：长推理任务跑一半 `RATE_LIMIT: 429 {"code":50602,"message":"... TPM limit reached"}`，
   agent 停在「Now I'll add ...」不再动手（退出码 0 或 1 都可能）。issue #27 用 29B 三次全废，
   挂 `model:strong`（DeepSeek-V4.1-Flash）后一次成。已写进 `docs/dispatch.md`。

## 四、现在这套东西能做什么

人写一张 Issue（目标 / 验收标准 / 约束三段）→ 打 `agent:ready` →
计划任务每 5 分钟轮询 → 隔离 worktree 里 headless 干活 → 调度器自己跑门禁 →
评审层看 diff → commit + push 分支 → 开 PR → CI → **人只做一件事：点 squash merge**。

不可自动的部分仍然不可自动：合并 main、改 workflows、加依赖、改断言凑绿、删数据。
